## Задание 1. Инвариантный контейнер

Напишите инвариантный обобщённый класс `Stack` (стек) с методами:
- `push(self, item: T) -> None`
- `pop(self) -> T`

**Требования:**
- Используйте `TypeVar("T")` без флагов
- Убедитесь, что mypy ругается на попытку присвоить `Stack[Dog]` переменной типа `Stack[Animal]`

**Проверка:**
```python
class Animal: pass
class Dog(Animal): pass

dog_stack: Stack[Dog] = Stack()
animal_stack: Stack[Animal] = dog_stack   # mypy должен показать ошибку
```

## Задание 2. Ковариантный контейнер

Напишите класс `ReadOnlyStack`, который умеет только `peek(self) -> T_co` (посмотреть верхний элемент, не удаляя), без `push`.

**Требования:**
- `TypeVar("T_co", covariant=True)`
- mypy НЕ должен ругаться на присвоение `ReadOnlyStack[Dog]` переменной `ReadOnlyStack[Animal]`

**Проверка:**
```python
dog_stack: ReadOnlyStack[Dog] = ReadOnlyStack(Dog())
animal_stack: ReadOnlyStack[Animal] = dog_stack   # должно пройти без ошибок
```

## Задание 3. Контравариантный обработчик

Напишите класс `Validator(Generic[T_contra])` с методом `validate(self, item: T_contra) -> bool`.

Реализуйте `AnimalValidator(Validator[Animal])`, который считает валидным любое животное с непустым именем.

**Требования:**
- `TypeVar("T_contra", contravariant=True)`
- Функция `check(v: Validator[Dog], d: Dog) -> bool`, которая должна принимать `AnimalValidator` без ошибок mypy

**Проверка:**
```python
def check(v: Validator[Dog], d: Dog) -> bool:
    return v.validate(d)

check(AnimalValidator(), Dog())   # должно пройти mypy без ошибок
```

## Задание 4. Определи вариантность сам

Для каждого из следующих классов определите (в комментарии), какой должна быть вариантность — invariant, covariant или contravariant — и объявите `TypeVar` правильно:

1. `Repository[T]` с методами `save(self, item: T) -> None` и `get_all(self) -> list[T]`
2. `Serializer[T]` с единственным методом `serialize(self, item: T) -> str`
3. `Factory[T]` с единственным методом `create(self) -> T`

**Проверка:** для каждого класса напишите короткий пример использования, который mypy должен принять, и (в комментарии) пример, который должен вызвать ошибку.

## Задание 5 (со звёздочкой). Callable и вариантность

Изучите, как typing описывает `Callable[[Arg], Ret]`, и объясните комментарием в коде:
- Почему тип аргумента (`Arg`) ведёт себя контравариантно
- Почему тип результата (`Ret`) ведёт себя ковариантно

Затем напишите функцию `apply(fn: Callable[[Animal], str], a: Animal) -> str`, и подберите такую функцию `fn`, объявленную как `Callable[[Dog], str]`... а затем — как `Callable[[object], str]`. Проверьте mypy на обоих вариантах и объясните разницу в комментарии.

## Бонус для тех, кто закончил раньше
Встроенный `list` в Python — инвариантен, а `tuple` — ковариантен по каждому из своих элементов. Попробуйте объяснить своими словами (в комментарии), почему у `tuple` это безопасно, а у `list` — нет, вспомнив, чем `tuple` принципиально отличается от `list`.
